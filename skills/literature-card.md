# 文献卡片生成

把论文变成**可累积、可检索、可复用**的卡片文件，而不是聊天记录里的一段文字。
卡片是后续综述、开题、对比分析的唯一数据源，所以宁可少写，不可编造。

## 输入判定

1. 用户给了文件路径或目录：用 `glob` / `read` 打开，确认文件真实存在。
2. 用户直接粘贴了全文：以粘贴内容为准，不要再去找文件。
3. 用户只说"读一下我的文献"：先在当前工作目录找 `papers/`、`literature/`、`pdfs/`，找不到就问路径，不要猜。

## 步骤

### 1. 读取

- 先读开头部分，确认标题、作者、期刊/会议、年份、摘要。
- 再读方法、结果、讨论、结论。长文用 `read` 的 offset/limit 分段，不要一次吞掉整篇。
- PDF 是扫描件、提取不出文字时，**停下来告诉用户**"这份 PDF 没有文本层，需要 OCR 或粘贴全文"，不要凭标题和常识编内容。
- 抽取文本乱码、断行、缺页时：先清洗（去页眉页脚、修连字符、去重复行），把清洗稿写到 `papers/txt/`，再基于清洗稿读；卡片里注明"文本来自抽取，可能有错漏"。

### 2. 抽取

按下面的字段逐项找原文依据；找不到就写【原文未提及】，不要推测。

- 研究问题（作者要解决什么）
- 核心创新点（相对已有工作新在哪）
- 研究方法与数据来源（样本、数据量、实验设计）
- 主要研究结论（作者自己的结论，不是你的评价）
- 研究局限性（作者承认的 + 方法上显而易见的）
- 可借鉴点 / 后续方向

### 3. 写卡片

路径：`cards/<slug>.md`。slug 用标题的英文小写连字符；中文标题用拼音或核心英文术语；重名时加年份。

```markdown
# 文献卡片：《论文完整标题》

**一句话结论：**（一句话说清这篇论文做了什么、结论是什么）
**作者：**
**期刊/来源 & 发表年份：**
**研究问题：**
**核心创新点：**
**研究方法与数据来源：**
**主要研究结论：**
**研究局限性：**
**可借鉴点 / 后续可拓展研究方向：**
**关键词：**
**原文文件：**（原始文件绝对路径；若基于抽取文本，另附抽取稿相对工作区根目录的路径）
```

同一篇论文重复生成时，覆盖原文件，不要产生 `-2`、`-copy`。
`原文文件` 必须能让人回找到原文：优先写原始文件绝对路径，再附抽取文本路径，例如
`C:\...\论文.pdf`（抽取文本：`academic-test/papers/txt/xxx.txt`）。

### 4. 多篇处理

- 2–3 篇：逐篇读、逐篇写卡片，然后写对比。
- 超过 3 篇：如果环境支持子 Agent，按每 1–2 篇一个子任务并行读，**每个子任务只写自己的卡片文件**；主 Agent 不要重复读全文，只读子任务产出的卡片。没有子 Agent 就顺序处理，并在开始时告诉用户大概需要多久。
- 全部卡片写完后，先判断这批文献是否属于**同一研究问题**：看研究对象、学科、方法是否可比。
  - 若明显不是同一问题（例如一篇当代政策实证、两篇近代经济史），在 `_comparison.md` 开头直接写明"这批文献不构成同一问题的对话"，给出分组建议，**不要为了凑格式硬做结论对比**；
  - 可比时再按下面的结构写。
- 写 `cards/_comparison.md`：

```markdown
# 文献横向对比小结

## 共同关注的问题
## 方法差异
## 结论冲突点
## 尚未被回答的问题（研究缺口）
```

## 质量约束

- 严格基于原文；缺失信息标【原文未提及】。
- 不写"本文是一篇优秀的论文"这类空话。
- 卡片正文用标准 Markdown，方便导入 Zotero / Notion / Obsidian。
- 不把整篇论文复制进卡片，只保留结构化信息。
- **不记录与学术判断无关的个人信息**：学号、身份证号、手机号、住址、私人联系方式一律略去；作者姓名与单位保留。
- 先给"一句话结论"，详细数据放后面，保证卡片能 30 秒扫读、也能回查细节。

## 完成时报告

- 读了哪些文件（路径）
- 生成了哪些卡片（路径 + 标题）
- 哪些字段缺失、哪些文件读取失败
- 下一步建议（继续读下一批 / 生成综述大纲）
